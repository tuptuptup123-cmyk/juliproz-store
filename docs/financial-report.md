# Financial report

Statistics → Financial report is restricted to an approved owner with MFA and a current admin session. Other employees keep the existing sales-history access; costs, customer references, consignment terms and finance audit are never exposed through public products or browser storage.

Confirmed catalogue sales create a private financial entry in the same transaction. The original sale, inventory update and cancellation flows are unchanged. Sale date, quantity, gross amount and commission/order classification are immutable in the finance form. Cancellation follows the sales ledger and removes the amount from completed revenue; any net payment still recorded is shown as pending refund. Deleting or editing a catalogue product cannot change the financial snapshot.

For consignment, owners set an agreed payout **per unit** on current catalogue items. Future sales snapshot it times quantity. Historical sales retain their agreed amount. Actual owner payment and expenses are recorded per transaction. Commission income uses the full agreed owner obligation, not only cash already paid.

Customer orders can be entered manually, with an optional catalogue reference, opening/completion dates, gross price, net received payment, purchase cost, expenses and status. Completing this manual financial order does not change catalogue inventory. If a catalogue sale exists, use **Link to sale**: matching amount, quantity, classification and optional product are required; conflicting financial values are rejected. The original order is retained as linked, the sale becomes the single reportable operation, and both before/after records are audited. Linked orders cannot be edited separately.

The report uses sale/completion date for completed operations and opening date for active orders. Receipt and payout totals are current balances **for the selected operations**, not a dated cash-flow statement. Null means unknown; zero must be explicit. Unknown-cost trades are excluded from the calculated-income subtotal and counted in the coverage warning. Operating overhead and taxes are not included. Pending orders and current consignment inventory values are not revenue. The consignment portfolio is a current snapshot, independent of the date range. Commission and order filters can overlap; the overview counts each operation once.

All writes use expected revisions; manual order creation uses a stable client-generated UUID to prevent duplicate creation on retries. Row history retains monetary changes, actor and timestamp. Source sale and financial writes take locks in a consistent order. Private tables have RLS with no direct client grants, and guarded RPCs reject anonymous, non-owner, unapproved, MFA-incomplete and expired-session callers.

Verification: `node --test tests/*.test.cjs`, `node tests/admin-finance.browser.cjs` with Playwright (320/390/1280 px), and `supabase/finance-probes.sql` as a rollback-only database probe. All identities and sales in the SQL probe are synthetic. The browser suite mocks service responses; SQL probes independently verify real guarded RPCs, source triggers, accounting, linking, cancellation, concurrency revisions and authorization.
