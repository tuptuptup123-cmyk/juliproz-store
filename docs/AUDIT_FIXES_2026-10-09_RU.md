# Исправления двух внешних аудитов — 09.10.2026

## Выполнено
- Размеры: 38,40 → два варианта; 16,17,18 → три; 36,5 → 36.5. 2XL/3XL объединяются с XXL/XXXL. Уже повреждённых значений по предложенному запросу в products не найдено.
- Порог сообщения 3500 символов; повторный заблокированный переход не показывает успешное оформление.
- Публичное описание отображается экранированным текстом с переносами строк; поле в админке помечено публичным. Проверка описаний не нашла email/телефон по применённым шаблонам, это не семантическая гарантия отсутствия любых внутренних заметок.
- Поддерживаемые валюты согласованы между формой и базой. Склонения для 21/22/112 исправлены.
- Сетевые ошибки/5xx обновления токена сохраняют сессию, карточку и обработанные фото; подтверждённые 400/401/403 завершают сессию.
- Обновление каталога при возврате ограничено интервалом 60 секунд; неизменная выдача не перерисовывается.
- Карточка имеет отдельную кнопку открытия без вложенной кнопки в role=button. Диалог закрывается Escape, удерживает клавиатурный фокус и возвращает его.
- SDK Telegram и клиентские скрипты загружаются defer с сохранением порядка. Permissions-Policy добавлена витрине. На живом сайте проверено: admin.html и photo-worker.js получают по одной собственной CSP, конфликтующих политик нет.
- UUID администратора убран из публичного config. Статус паузы выдаёт защищённый RPC только текущему администратору.
- Льготный вход MFA без verified-фактора исключён из серверной функции. Новый администратор проходит enrollment до доступа к инвентарю.
- Кнопка настройки MFA доступна владельцу на паузе. Успешная проверка AAL2 атомарно включает enforcement и удаляет только паузу текущего владельца. До ввода реального кода прежняя пауза остаётся: автоматически снять её небезопасно для доступа.
- Автоматического триггера на auth.users нет. Остаточные политика назначения админов и функция удалены, старые приглашения закрыты от клиентских и Auth-ролей. Членство владельца и строки приглашений сохранены.
- Обе таблицы старого загрузчика были пусты и удалены миграцией с проверкой пустоты. Старый Edge загрузчик остаётся инертным 410.
- Проверка каждого URL photos ограничивает длину 2048 и число 20. Действующие CHECK products_trusted_image/products_trusted_photos подтверждены.
- Аналитика запускается только после согласия. Отказ/отзыв останавливает новые события и очищает локальные аналитические ID; настройки доступны в меню. Добавлена фактическая страница конфиденциальности. Статистика учитывает согласившиеся устройства.
- Общие лимиты ingest: 120 запросов/мин и 10000/день; 30/мин на fingerprint и visitor; новые сессии 20/мин глобально и 5/мин на fingerprint. Общие ограничения работают независимо от подделки IP/visitor. Изменения и лимиты в базе атомарны.
- Для IP отдельный серверный случайный секрет в закрытой таблице, суточная соль доступна только service_role. Edge ограничивает тело по потоку до 2048 байт, кеширует суточную соль, задаёт таймауты запросов.
- README актуализирован: пользовательская кнопка «Удалить» намеренно удаляет товар после подтверждения, фотографии сохраняются. Исторические rollback/pause SQL не входят в путь установки нового релиза.

## Проверки
30 unit-тестов; браузерные проверки на 390 и 1280 px: 150 нажатий, согласие/отзыв, отсутствие идентификаторов до согласия, размеры, безопасное описание, фокус/Escape, валюты. Админка дополнительно проверена на 320/390/768/1280/1920 px.
В реальном Edge: чужой Origin 403, корректный heartbeat 202. Тест лимита новых сессий в транзакции с rollback: 5 приняты, шестая отклонена. Соль имеет длину 64, но её значение не выгружалось.
Синтетический обычный authenticated: MFA false, 0 администраторов, 0 скрытых товаров, 0 событий; защищённые RPC отказали. Аноним и authenticated не имеют права вызова RPC соли.
Public signup проверен через /auth/v1/settings: disable_signup=true.

## Остаётся явно
1. Владелец: Настройки → Безопасность → Включить двухфакторную проверку → код из имеющегося аутентификатора. До успешного подтверждения его пауза действует. Возможность добавить запасной фактор сохраняется после включения.
2. Supabase Auth: проверить/выставить серверную длину пароля 12 и включить Leaked Password Protection, если доступно на тарифе. Advisor по-прежнему сообщает, что защита выключена. Подключённые инструменты не предоставляют управление этими настройками.
3. Публичные события не являются достоверными подтверждениями покупки; статистику всё ещё можно искажать в пределах лимитов. Проверка Origin не считается аутентификацией; источник X-Forwarded-For не доказан как неподделываемый. Общие лимиты ограничивают расход даже при его подделке.
4. Rate-limit Telegram webhook остаётся best-effort в памяти инстанса. Для распределённого лимитера нужны отдельный закрытый backend/секреты или Redis; текущий релиз не внедряет новую инфраструктуру.
5. Корзина оформляет заявку менеджеру, без оплаты и атомарной серверной брони. Публичные фото остаются доступны по старым URL после скрытия вещи. Сторонний SDK Telegram без SRI сохраняется для совместимости. Политике конфиденциальности нужна юридическая проверка применимости к бизнесу.
6. Нет проверки всех внешних аккаунтов/журналов провайдеров, нагрузки или полного внешнего pentest. Исторические SQL не должны запускаться подряд.
